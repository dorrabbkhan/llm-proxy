# llm-proxy v1.0.1 — Design Spec

**Date:** 2026-10-26 · **Status:** approved by owner 2026-10-26 (D1–D5 as recommended) · **Roadmap:** `docs/roadmap.md` (Phase 1) ·
**Parent spec:** `docs/superpowers/specs/2026-10-26-llm-proxy-roadmap-design.md`

## 1. Purpose

Make what v1.0 already claims actually true against real upstreams, and make the repo ready for outside
users and contributors. No new features: v1.0.1 fixes correctness, makes failures honest, and adds the
tests, CI and paperwork that every later version depends on.

### 1.1 Why now
v1.1 (streaming, tools, launch) builds directly on the request path, the error path and the test setup.
Bugs in those paths would be copied into every streaming adapter, and the launch would send new users to a
quick-start that likely fails. Fixing them first is cheaper than fixing them after v1.1.

### 1.2 Evidence (found by reading the code, 2026-10-26)
| # | Finding | Where | Effect |
|---|---|---|---|
| E1 | The Ollama adapter omits `stream` when the client did; Ollama streams NDJSON by default | `ollama.adapter.ts:128` | README quick-start (OpenAI → Ollama) gets NDJSON back |
| E2 | Non-JSON upstream bodies become `null` silently | `http-client.ts:83` (`res.json().catch(() => null)`) | E1 surfaces as a confusing 500 `TRANSFORM_ERROR` from the adapter |
| E3 | `stream: true` is forwarded upstream but replies are parsed as JSON | `proxy.service.ts`, all adapters | Streaming clients get a crash or a non-streamed body they can't read |
| E4 | Every non-2xx upstream reply becomes `502 UPSTREAM_ERROR` | `proxy.service.ts:133` | "Model not found" (404), bad request (400) and rate limit (429) all look like proxy failures |
| E5 | Errors use a custom `{error:{message,code,status}}` shape | `utils/errors.ts`, `middleware/error-handler.ts` | SDKs can't parse them into their native exception types |
| E6 | Client auth only reads `Authorization: Bearer` | `middleware/require-api-key.ts` | Anthropic clients (Claude Code) send `x-api-key`; Gemini clients send `x-goog-api-key` or `?key=` — locked out when `PROXY_API_KEY` is set |
| E7 | Tests never touch a real upstream | `tests/mocks/upstreams.ts` | E1–E3 pass all 315 tests |
| E8 | No LICENSE, CI, CONTRIBUTING, SECURITY.md; `package.json` says ISC with no author | repo root | Others can't adopt or contribute safely |
| E9 | `.gitignore` lines with trailing `# comments` | `.gitignore` | `.vscode/`, `.idea/`, `.DS_Store`, `*.tsbuildinfo` aren't actually ignored |
| E10 | Gemini-format clients name the model in the URL, but `toCanonicalRequest` hard-codes `"gemini-pro"` and `proxy.service` reads `body.model` (absent) | `gemini.adapter.ts:71`, `proxy.service.ts` | Every Gemini-SDK request is sent upstream with model `"default"` (found while planning; added to the approved spec) |
| E11 | Any `POST /v1beta/models/<m>:<method>` is treated as a chat request | `PROVIDER_ROUTES.gemini` | `:countTokens`, `:embedContent` and `:streamGenerateContent` are silently answered as `generateContent` |

E1 is confirmed by Ollama's API documentation (`stream` defaults to `true` on `/api/chat`) but not yet by a
live run. Task 1 records the live confirmation in `docs/decisions.md` before the fix lands.

### 1.3 Success criteria
- The README quick-start works verbatim against a live Ollama with `qwen2.5:0.5b`.
- Every error a client can receive on a provider route is in its own provider's error shape, with a
  meaningful status.
- `PROXY_API_KEY` works with the official OpenAI, Anthropic and Gemini SDKs' default auth headers.
- `npm run test:live` passes against a live Ollama; CI runs `./scripts/check.sh` on every PR.
- The repo has an Apache-2.0 LICENSE and a working CLA check before the first outside PR is merged.
- No existing test's expected values change, except the error-shape assertions §3.3 replaces (listed in
  the plan, owner-reviewed).

## 2. Scope

### 2.1 In v1.0.1
1. Ollama non-streaming fix and strict upstream body parsing (E1, E2).
2. Honest streaming refusal (E3).
3. Canonical errors in the client's dialect, with upstream status mapping (E4, E5).
4. Client auth in each provider's native header (E6).
5. Live smoke suite (E7).
6. CI, licence, CLA and contributor docs (E8, E9).
7. README and CHANGELOG updates; version 1.0.1.

### 2.2 Not in v1.0.1
- Streaming translation, tool calling in non-OpenAI adapters (v1.1).
- Serving more than one source format per instance (v1.2). §3.3's design must not block it.
- Renaming the package (decided before v1.1 publishes to npm).
- Publishing to npm or GHCR (v1.1).

### 2.3 Non-goals
- Faking a stream by wrapping a non-streamed reply in SSE. It needs per-adapter stream writers — v1.1 work —
  and a half-correct stream is worse than a clear 501.
- Retrying on more statuses, or changing the timeout/retry defaults.

## 3. Design

### 3.1 Ollama non-streaming and strict parsing (E1, E2)
- `ollama.adapter.ts` `fromCanonicalRequest` always sets `stream` explicitly: `request.stream ?? false`.
  (After §3.2, `true` never reaches an adapter in v1.0.1, but the adapter stays correct on its own.)
- The other adapters are checked for the same default: OpenAI and Anthropic default to non-streaming;
  Gemini selects streaming by endpoint, not by a body field. No change, but each gets a test asserting the
  outgoing body for a request without `stream`.
- `http-client.ts` stops swallowing parse failures. If the upstream returns a 2xx whose body isn't valid JSON,
  it throws `UpstreamError` (502) with message
  `Upstream returned a non-JSON response (content-type: <type>)` and the first 200 characters of the body
  in the non-production `details`. Non-2xx non-JSON bodies keep `body: null` and go through §3.3.
- **Model from the path (E10).** `ProviderRoute` gains an optional `modelFromPath(path)`; Gemini's chat route
  returns the `<m>` in `/v1beta/models/<m>:generateContent`. `proxy.service` uses it to set
  `canonical.model` when present, and builds the target URL from `canonical.model` instead of `body.model`.

### 3.2 Honest streaming refusal (E3)
- After the source request is converted and validated, if `canonical.stream === true`, `proxy.service`
  throws a new `NotSupportedError` (status 501, canonical kind `unsupported`) with message
  `Streaming is not supported yet (planned for v1.1). Send "stream": false.`
- Gemini's streaming endpoint (`:streamGenerateContent`) is recognised by the route (an optional
  `isStreamPath(path)` on `ProviderRoute`) and refused the same way.
- **Other Gemini methods (E11):** a `POST /v1beta/models/<m>:<method>` whose method isn't `generateContent`
  or `streamGenerateContent` returns 501 `unsupported` in the Gemini dialect (`<method> is not supported`).
- The refusal happens before any upstream call.

### 3.3 Canonical errors in the client's dialect (E4, E5)

**Canonical error** (new, in `canonical.types.ts` with its Zod schema in `canonical.schema.ts`):
```ts
export type CanonicalErrorKind =
  | "invalid_request"   // 400
  | "authentication"    // 401
  | "permission"        // 403
  | "not_found"         // 404
  | "request_too_large" // 413
  | "rate_limit"        // 429
  | "unsupported"       // 501
  | "upstream"          // 502
  | "unavailable"       // 503
  | "timeout"           // 504
  | "internal";         // 500

export interface CanonicalError {
  kind: CanonicalErrorKind;
  status: number;        // HTTP status sent to the client
  message: string;       // human-readable; never contains prompt text or keys
  retryAfterSeconds?: number;
}
```

**Adapter interface** gains two functions (every adapter implements both, contract-tested like the rest):
- `toCanonicalError(status: number, body: unknown): CanonicalError` — reads that provider's error body
  (falling back to a generic message when the body is missing or unrecognised).
- `fromCanonicalError(err: CanonicalError): unknown` — the body in that provider's native shape:

| Provider | Body | Kind → provider type |
|---|---|---|
| OpenAI | `{"error":{"message","type","param":null,"code"}}` | `type`: `invalid_request_error`, `authentication_error`, `permission_error`, `not_found_error`, `rate_limit_error`, `api_error`; `code` = kind |
| Anthropic | `{"type":"error","error":{"type","message"}}` | `invalid_request_error`, `authentication_error`, `permission_error`, `not_found_error`, `request_too_large`, `rate_limit_error`, `api_error` (unsupported, upstream, internal), `timeout_error` (timeout), `overloaded_error` (unavailable) |
| Gemini | `{"error":{"code","message","status"}}` | `INVALID_ARGUMENT`, `UNAUTHENTICATED` (also 400 + `API_KEY_INVALID` in `error.details[]`), `PERMISSION_DENIED`, `NOT_FOUND`, `RESOURCE_EXHAUSTED` (rate_limit, request_too_large), `UNIMPLEMENTED`, `INTERNAL`, `UNAVAILABLE`, `DEADLINE_EXCEEDED` |
| Ollama | `{"error":"<message>"}` | message only |

The exact tables are part of the contract tests; Task 3 confirms each against the provider's current docs and
records the sources in `docs/decisions.md`.

**Upstream status mapping** — what the client sees when the upstream fails:

| Upstream | Client status | Kind | Reason |
|---|---|---|---|
| 400, 422 | 400 | invalid_request | The client's request is wrong for the target; pass the upstream message through |
| 404 | 404 | not_found | Almost always "model not found" — the client can fix it |
| 413 | 413 | request_too_large | Client can shrink the request |
| 429 (after retries) | 429 | rate_limit | Pass `Retry-After` through when present |
| 401, 403 | 502 | upstream | The *proxy's* upstream key is wrong; a 401 would wrongly tell the client its own key is bad. Message: `Upstream <provider> rejected the proxy's credentials (<status>)` |
| 503, 529 (after retries) | 503 | unavailable | |
| Other 5xx | 502 | upstream | |
| Timeout | 504 | timeout | (unchanged) |
| Transport failure | 502 | upstream | (unchanged) |

**Wiring:**
- `ProxyError` subclasses each map to one `CanonicalError` (`toCanonical()` method).
  `UpstreamError` uses the target adapter's `toCanonicalError` on the upstream status and body, then the
  mapping table above.
- A small middleware placed before auth and the body parser resolves the source provider from the request
  path and records it on `res.locals.sourceApi`. The error handler converts any error to a `CanonicalError`
  and renders it with `adapters[res.locals.sourceApi].fromCanonicalError`, setting `Retry-After` when
  present. This is per-request, so v1.2's several-formats-per-instance needs no change here.
- So auth failures (§3.4) and body-parser errors (413, malformed JSON → 400) on provider paths also render
  in the source dialect.
- Errors outside a provider route (404 for unknown paths, `/health`) keep today's generic shape.
- Unknown errors are `internal` (500); the message is generic in production, as today.
- **Privacy:** upstream error bodies are logged at `warn` with only `status`, `type/code` and the first 200
  characters of the message. Upstream bodies are no longer copied wholesale into `details`.

### 3.4 Client auth in each provider's native header (E6)
When `PROXY_API_KEY` is set, a request is authenticated if **any** of these carries the key:
`Authorization: Bearer <key>` (OpenAI, Ollama, and Anthropic's `ANTHROPIC_AUTH_TOKEN`), `x-api-key`
(Anthropic), `x-goog-api-key` or the `?key=` query parameter (Gemini). Every comparison stays timing-safe.
These client credentials are never forwarded upstream; the upstream gets the proxy's own key, as today.
The rejection is a 401 `authentication` error in the source dialect.

### 3.5 Live smoke suite (E7)
- `tests/live/*.live.test.ts`, run by `npm run test:live` with its own vitest config; excluded from
  `npm test` and `./scripts/check.sh`.
- Starts the real app in-process with `TARGET_API` set per test and the real upstream URL.
- **Ollama (always):** `OLLAMA_API_BASE_URL` (default `http://localhost:11434`), model from
  `LIVE_OLLAMA_MODEL` (default `qwen2.5:0.5b`). If Ollama isn't reachable, the suite fails with a clear message
  — it never silently passes.
- **Paid providers (opt-in):** OpenAI, Anthropic and Gemini cases run only when their `*_API_KEY` is set, with
  a cheap model from `LIVE_<PROVIDER>_MODEL`, `max_tokens` ≤ 16. Skipped cases are listed in the output.
- **Cases per available target**, each driven through every source format: one chat round trip (non-empty
  text, usage present); the model list; an unknown model → 404 `not_found` in the source dialect; `stream:
  true` → 501 in the source dialect.
- **Shape assertions only.** Never assert generated text; LLM output isn't deterministic.
- Nightly GitHub Actions workflow: an Ollama service container, `ollama pull qwen2.5:0.5b` (cached), then
  `npm run test:live`. Paid keys come from repository secrets only if the owner adds them.

### 3.6 CI, licence, CLA and contributor docs (E8, E9)
- `.github/workflows/ci.yml`: on PRs and pushes to main — Node 22, `npm ci`, `./scripts/check.sh`, plus a
  Docker build (no push).
- `.github/workflows/live.yml`: nightly and on manual dispatch (§3.5).
- `LICENSE` (Apache-2.0 text) and `NOTICE`; `package.json` `license: "Apache-2.0"`, `author`, `repository`.
- **CLA:** `CLA.md` (adapted from NeoPhylo's, licensor named as the owner) and the CLA Assistant Lite GitHub
  Action, with signatures stored on a `cla-signatures` branch. No external service.
- `CONTRIBUTING.md` (setup, `./scripts/check.sh`, the fixture rule, how to add a provider, CLA),
  `SECURITY.md` (private vulnerability reporting via GitHub), issue templates (bug, provider request,
  feature) and a PR template.
- `.gitignore`: move trailing comments to their own lines.

### 3.7 README, CHANGELOG, version
- README: the quick-start uses `qwen2.5:0.5b` and works without `"stream": false` (it's the default now);
  new sections on errors, auth headers, live tests and the licence; known limitations updated (streaming
  returns 501).
- `CHANGELOG.md` (Keep a Changelog format) starting at 1.0.1, noting the error-shape change as a
  compatibility note: clients that parsed the old custom shape must use their SDK's errors.
- `package.json` version `1.0.1`. The owner tags the release.

## 4. Testing

| Area | Tests |
|---|---|
| §3.1 | Outgoing Ollama body has `stream: false` when the client omitted it; each other adapter's outgoing body for a request without `stream`; 2xx non-JSON upstream → 502 with the content-type message (msw returns NDJSON) |
| §3.2 | `stream: true` from each source format → 501 in that format, and no upstream call (msw asserts zero requests); Gemini `:streamGenerateContent` → 501 |
| §3.3 | Contract: every adapter's `fromCanonicalError` for every kind matches a fixture of that provider's documented error body; `toCanonicalError` round-trips those fixtures. Integration: each row of the upstream mapping table, for every source format (generated per pair like `pairs.test.ts`); `Retry-After` passthrough; body-parser 413 and malformed JSON in the source dialect |
| §3.4 | Each header style accepted; wrong key in each style → 401 in the source dialect; client key never appears in the upstream request |
| §3.5 | The live suite itself; a unit test that the live config is excluded from `npm test` |
| §3.6 | CI green on the PR that adds it |

**Fixtures:** the new error-body fixtures are new files (allowed by the fixture guard). No existing fixture or
snapshot changes. Existing integration tests that assert the old custom error shape
(`proxy.test.ts`: "returns 502 when upstream fails", "returns 502 for upstream 401", the auth tests) get new
expected bodies; their status codes stay the same. That task is marked OWNER REVIEW so the changed
assertions are checked by a human, not treated as loosening.

## 7. Risks
| Risk | Mitigation |
|---|---|
| Provider error shapes differ from docs in practice | Live suite asserts the not-found path against real upstreams; fixtures record the doc source |
| Ollama service container makes nightly CI slow | Cache the model directory; nightly only, never on PRs |
| §3.3's adapter interface addition conflicts with v1.1's stream functions | Both are additive methods on `ProviderAdapter`; v1.1's spec builds on this one |
