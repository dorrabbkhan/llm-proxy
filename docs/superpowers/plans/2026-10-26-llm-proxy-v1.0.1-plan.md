# llm-proxy v1.0.1 (Correctness patch and public hygiene) Implementation Plan

> **For agentic workers (Devin):** Run each task in its own session with `/llm-proxy-task v1.0.1 <N>`. One task → one branch (`v1.0.1/task-<N>-<short-name>`) → one PR. Steps use checkbox (`- [ ]`) syntax. Read `AGENTS.md`, this plan's Global Constraints and Review Focus, and the spec sections each task names. Use `./scripts/check.sh quick` while iterating and `./scripts/check.sh` before pushing. Verify every write with `git diff`.

**Goal:** Make v1.0's claims true against real upstreams — Ollama works, Gemini clients get their model, every error arrives in the client's own provider format, `PROXY_API_KEY` works with every SDK — and make the repo ready for outside contributors.

**Architecture:** Errors get a canonical form (`CanonicalError`) and every adapter learns to read and write its provider's error body, exactly as it already does for requests and responses. A small middleware records the source provider per request, so the error handler can render any error — including auth and body-parser errors — in that dialect. Upstream failures pass through a single policy function (`toClientError`) that decides what the client sees. A separate, opt-in live suite runs the real app against a real Ollama.

**Tech Stack:** As v1.0 (Node ≥ 20, TypeScript 5 strict, Express 5, Zod 4, pino, vitest 3, msw 2, supertest). Added: none at runtime. CI: GitHub Actions, `contributor-assistant/github-action` (CLA Assistant Lite), the `ollama/ollama` image for the nightly live job.

**Spec:** `docs/superpowers/specs/2026-10-26-llm-proxy-v1.0.1-design.md`. Parent: `docs/superpowers/specs/2026-10-26-llm-proxy-roadmap-design.md`.

**Decided with the owner (2026-10-26), reflected in the spec:** D1 upstream 401/403 → client 502; D2 CLA Assistant Lite; D3 error-shape change ships in 1.0.1 with a CHANGELOG note; D4 nightly live CI is Ollama-only until the owner adds paid keys as secrets; D5 `qwen3:0.6b` is the default live model.

**Prerequisite (owner):** commit the roadmap, both specs, this plan and the agent/conductor setup to `main` before Task 1 starts.

## Global Constraints

- **No existing expected value changes,** except the error-body assertions Task 4 replaces (listed in Task 4, OWNER REVIEW). Existing fixtures and contract snapshots are never edited; new fixture files are allowed.
- **Adapters stay independent:** an adapter imports only from `src/types/` and `src/utils/`, never another adapter. Provider policy (which upstream status the client sees) lives in `src/services/upstream-errors.ts`, not in adapters.
- **Canonical changes are named:** this version adds exactly `CanonicalErrorKind`, `CanonicalError`, and `toCanonicalError` / `fromCanonicalError` on `ProviderAdapter`. Each is mirrored in `canonical.schema.ts` where it is data.
- **Kinds and statuses** (spec §3.3), verbatim: `invalid_request` 400, `authentication` 401, `permission` 403, `not_found` 404, `request_too_large` 413, `rate_limit` 429, `internal` 500, `unsupported` 501, `upstream` 502, `unavailable` 503, `timeout` 504.
- **Messages** (spec, verbatim): streaming refusal `Streaming is not supported yet (planned for v1.1). Send "stream": false.`; non-JSON upstream `Upstream returned a non-JSON response (content-type: <type>)`; upstream credentials `Upstream <provider> rejected the proxy's credentials (<status>)`; Gemini method `<method> is not supported`.
- **Privacy:** no prompt text, completion text or key (client or upstream) in any log line, error message or `details`. Upstream error bodies are logged as `status`, provider `type/code`, and at most the first 200 characters of the message — and no message at all for upstream 401/403.
- **No network in `npm test`.** Real upstreams only in `tests/live/`, run by `npm run test:live`.
- **No new runtime dependencies.**
- **Owner-only:** fixture/snapshot changes to existing files, LICENSE and CLA content approval, adding repository secrets, enabling the CLA app/branch protection, merging, tagging `v1.0.1`.

## Review Focus

1. **Upstream error bodies that aren't the provider's documented shape** — empty, HTML from a reverse proxy, plain text, or JSON of another shape: `toCanonicalError` falls back to `Upstream <provider> returned <status>` with the kind from the status, never throws. → Task 3 (`toCanonicalError tolerates unrecognised bodies`), Task 4 (`HTML 502 page from upstream renders in source dialect`).
2. **Upstream messages that echo a key** (OpenAI's 401 includes a masked `sk-…` key): for upstream 401/403 the client gets only the credentials message and the log gets no message text. → Task 4 (`upstream 401 message never reaches client or log`).
3. **`Retry-After` in both forms** (delta-seconds and HTTP-date) and garbage: seconds pass through, a date becomes whole seconds from now (minimum 1), garbage is dropped. → Task 4 (`Retry-After forms`).
4. **Credentials in odd places:** empty `Bearer `, `?key=` with no value, a wrong key in one header and the right one in another (accepted — any match wins), and lowercase `bearer`. → Task 6 (`auth edge cases`).
5. **Gemini paths that aren't chat:** `:countTokens`, `:embedContent`, a model id containing `/` (`tunedModels/x`), and URL-encoded colons (`%3A`): non-chat methods get 501 in the Gemini dialect; the model id is decoded and passed through intact. → Task 2 (`modelFromPath decodes and keeps slashes`), Task 5 (`gemini non-chat methods → 501`).

Each line is pinned by a named test in the owning task.
